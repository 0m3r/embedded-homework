# Домашнє завдання — дослідження брязкоту кнопки

Код рахує переходи `HIGH → LOW` на GPIO21 через апаратне переривання. Логічний аналізатор одночасно записує реальну форму сигналу.

## Підключення

```text
ESP32 GPIO21 ─────┬──── D0 логічного аналізатора
                  │
                [ кнопка ]
                  │
ESP32 GND ────────┴──── GND логічного аналізатора
```

Кнопка використовує внутрішню підтяжку `INPUT_PULLUP`. `VCC` аналізатора не підключати.

## PulseView

1. Обрати `fx2lafw — Saleae Logic`.
2. Увімкнути канал `D0` і назвати його `GPIO21`.
3. Sample rate: `1 MHz`.
4. Capture: `10 M samples` або `10 s`.
5. За можливості встановити falling-edge trigger на `D0`.

Для кожного натискання рахувати переходи `HIGH → LOW`, бо саме їх реєструє ISR з режимом `FALLING`. Тривалість брязкоту вимірювати від першого переходу до моменту, після якого сигнал стабільно залишається `LOW`.

## Збірка, прошивка та monitor

```bash
pio run -d /home/om3r/Documents/PlatformIO/Projects/esp32-s3-embedded
pio run -d /home/om3r/Documents/PlatformIO/Projects/esp32-s3-embedded --target upload
pio device monitor -p /dev/ttyACM0 -b 115200
```

Вивід показує загальну кількість falling edges і приріст після останнього повідомлення:

```text
Falling edges: 4 (+3)
```

`+3` означає, що одне фізичне натискання створило три переходи `HIGH → LOW`.

## Аналіз

- Порівняти falling edges у PulseView з приростом ISR для кожного натискання.
- Середня тривалість: сума десяти вимірів, поділена на 10.
- Мінімальний debounce має бути більшим за найбільшу виміряну тривалість брязкоту з невеликим запасом.
- Різницю між PulseView та ISR перевіряти на дуже коротких імпульсах, перешкодах і межах окремих натискань.
